# 助理记忆加载

## 读取范围

助理使用唯一的线性 assistant 树，每次从最新主干任务继续，不接收用户选择节点。初始上下文只读取当前末端沿父链遇到的**第一个摘要及其后任务**，到摘要即停止；没有摘要时读取至根，空树返回空上下文。

例如历史为 `A → S1 → C → D → S2 → E → F`，下一次任务只载入 `S2、E、F`，使用 F 的工作区快照。不会读取 S2 的父节点 D，也不会先构建整棵树再截取。摘要由既有上下文管理生成，本模块不额外生成或改写记忆。

与[树结构](../../data/question-tree.md)、[节点落盘](../../data/node-persistence.md)共用原有表；探索模式打开完整树和选择历史节点的语义保持不变。历史原生生成仍完整持久化，但不作为初始上下文整批读取。

## 实现与一致性

[assistant_context.py](../../../../app/repository/assistant_context.py)承担局部父链解析与线性追加；[MySQLNodeRepository](../../../../app/repository/node_persistence.py)在助理 `load_agent_context/start_task` 路径调用它。

读取在同一 REPEATABLE READ 事务内完成：先验证树归属、用途和末端，再按 `(tree_id, id)` 沿父链点查，到最近摘要停止，最后批量读取这段路径正文、已完成中途消息及末端工作区。SQL 查询数随有效父链长度增长，无递归 CTE 深度限制，也不缓存完整助理树。没有摘要时必须走完整父链；工作区仍是完整权威快照，不按摘要截断。

每一步检查父节点存在、sequence 严格递减、主干标记和非生成中状态。末端必须是 `main_leaf_id` 指向的最新任务；已有生成中任务、游离末端、错误分支或跨树父链明确失败。读取摘要时验证正文与直接覆盖终点，完整覆盖起点在写入时校验；不会为重新审计旧摘要而越过当前边界读取历史。

追加任务持有树行锁并校验 revision，普通追加只读末端；需要新摘要时才读取有效父链并验证完整覆盖区间。摘要与新任务、继承工作区、主干指针、初始消息在同一事务提交。拒绝从旧节点继续或强制分支，稳定节点 ID 重放仍走原有幂等校验。该约束作用于助理生成路径；通用仓库的完整树读取/追加 API 仍保留，不应拿来绕过助理宿主规则。

## 记忆工具与装配

助理 [build_service](../../../../app/agent/assistant/factory.py) 可注入已有 `memory_backend`，按需装配[祖先记忆检索与查看](memory-retrieval.md)。初始上下文停止于摘要，并不删除更早记忆：模型主动检索时仍可查当前节点的祖先任务，命中附件后通过 Core 图像查看工具读取。

局部记忆读取本身不改变摘要推理强度，不把队列租约或请求标识注入模型。队列输入通过[消费处理器](../../../capability/application/assistant-consumption.md#输入渲染)转换为带来源首部的用户问题与本地附件引用。

## 验证

[局部读取测试](../../../../tests/test_assistant_context.py)覆盖摘要边界、无摘要深链、空树及损坏路径。[独立 MySQL 测试](../../../../tests/test_assistant_context_mysql.py)覆盖两次摘要后的实际读取、工作区继承、禁止选择/分支、摘要范围回滚、重放及真实助理服务调用替身模型并落盘；测试中禁止调用完整 `_snapshot`，并将旧摘要之前的正文损坏，验证正常读取不会触及它。

实库验证只使用显式 `ASSISTANT_STORAGE_TEST_MYSQL_PORT` 的临时 MySQL 测试库，约束同[助理存储测试](../../data/assistant-storage.md#迁移与验证)。不执行真实业务库迁移，不访问实际用户附件。
