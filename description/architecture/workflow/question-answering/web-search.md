# 网页搜索与正文读取

## 用途与装配

将 contract-service-be 的网页工具契约迁入公共 Core：先检索候选，再分页看摘要，最后按关注重点直接保留原文或精炼所选网页。搜索摘要不能当作已读取或已核实的正文。基础工具参数与文字页面渲染沿用参考项目，图片筛选与图文精炼在此基础上扩展；按本项目提示词规范，将两处字段说明和过期反馈中的缓存/驻留术语改为正文是否仍可读取，不暴露内部缓存机制，适配当前[工具提交与折叠机制](tool-content-contract.md)。

入口为 [web_search.py](../../../../app/agent/core/tool/web_search.py)、[web_page.py](../../../../app/agent/core/tool/web_page.py) 和 [web_page 子图](../../../../app/agent/core/subgraph/web_page/workflow.py)。`QuestionAgentService` 按可信 `(userid, tree_id)` 装配，探索和助理模式共用；无资源的基础 `build_core` 仍可独立使用，宿主也可通过注册函数显式注入这三个工具。

`search_web` 直接调用 DeepSeek Search HTTP 接口，不用模型路由；[外部专家](external-expert.md)仍调用 Responses。两者共用已有 DeepSeek 身份，搜索和生成预算独立。阅读语义判断与网页正文精炼使用本项目 vLLM MLLM，不消耗专家 Responses 会话。

## 三个工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `search_web` | `query` | 1—128 字符检索词。成功仅返回 `result_id/count`，不自动展示第一页。空结果不生成 ID。 |
| `view_web_search_results` | `result_id`、可选 `page` | 查看标题、URL、搜索摘要和来源标识。省略页码首次看第 1 页，其后看下一页。 |
| `open_web_page` | `source_id`、可选 `focus/keywords/page` | 首次读取或正文失效时需 focus；默认摘取相关原文，可明确要求全文保留、摘要或翻译。同一 focus 复用图文，第一页展示相关图片，指定 page=1 可重看。换 focus 重新抓取和处理。 |

`SearchWebArguments.query` 的实际字段 Schema 按 [DeepSeek Search 官方检索语法](https://api-docs.deepseek.com/guides/search/#query-operators)说明以下能力（2026-10-23 核对）：

| 需求 | 查询写法 |
| --- | --- |
| 指定站点或多个备选站点 | `site:arxiv.org`；`site:arxiv.org OR site:aclanthology.org`。 |
| 排除站点、词或完整词组 | `-site:example.com`、`-广告`、`-"release notes"`。 |
| 精确词组 | `"Attention Is All You Need"`，使用英文双引号。 |
| 结果页面语言 | `lang:en` 或 `lang:zh,en`；不是要求回答使用该语言。 |
| 页面发布日期 | `after:2025-01-01 before:2026-01-01`；也支持 `YYYY`。 |

运算符可组合，例如 `"Attention Is All You Need" site:arxiv.org lang:en`。描述要求一次聚焦一个目标，优先用已知原名，必要时分别搜索中英文或别名；只在确有需要时加限制，结果过少时逐步放宽非必要条件，用户明确要求仍需保留。未知标题不强加引号，不将零结果推断为资料不存在。日期约束作用于页面发布日期，不替代正文事实日期核验。

复杂问题拆分检索，完整 query（含运算符）须为 1—128 个 Unicode 字符，超长明确拒绝，不静默截断。查询语法直接传给供应商，本地不新增运算符解析或结果过滤，也不把文档未确认的 `filetype:`、`intitle:` 等语法描述为已支持能力。结果保持供应商原始顺序；模型只看到业务标题、链接、摘要和检索时间，不看到供应商路由、排名诊断或私有审计。

`source_id` 为搜索列表提供的完整来源标识，不能使用行号、结果集 ID 或任意 URL。`focus` 首次为非空文字、最多 4000 字符，说明目标、阅读范围及必要的摘要或翻译要求；后续省略或 null 沿用最近仍可读取的需求。`keywords` 最多 5 个、每个最多 24 字符，仅用于用户动作提示，不传入精炼模型、不参与缓存键。页码从 1 开始；非法页或到达末尾不推进游标。

网络失败、鉴权/额度/限流错误与成功零结果严格区分。面向模型的搜索失败回执为 `search_failed`，不会伪装为空结果；供应商状态码及脱敏响应留在当前用户树的有界私有搜索审计中。

## 网页读取子图

执行顺序为 `HTTP 读取 → 正文与候选图片提取 → 有界图片读取 → 阅读语义判断 → 原文直出或图文精炼 → finalize`。抓取、提取和正文处理失败直接收束，不用搜索摘要填补缺失正文；语义判断失败则保守进入精炼。

[阅读语义判断](../../../../app/agent/core/subgraph/web_page/routing.py)只将已有 `focus` 发给 MLLM，不发送网页正文、图片或 URL。单次普通 Chat Completions 返回严格的 `{"mode":"original"}` 或 `{"mode":"refine"}`；额外字段、非法 JSON、重复键、截断、拒答和工具调用均不接受。判断网络故障或输出不合法时不重试判断，沿用精炼；取消传播，不转为重试或成功。默认及不确定意图也走精炼，判断失败原始响应只进入私有审计，不注入精炼上下文。不新增工具参数、配置项或 HTTP 接口，使用现有 MLLM 连接及生成配置。

HTTP 默认总时限 30 秒、解压后上限 3 MiB、最多 5 次重定向，仅接受 HTML/XHTML。每次独立客户端，不携带应用登录凭据，不使用环境代理，不跨网页保存 Cookie；拒绝带用户名/密码的 URL。首次请求失败、超时、网页为空、类型不符或超限均不启动精炼。没有可用文字但存在候选图片时仍可继续；文字与图片都不可用时明确失败。网页本身可以正常重定向；带 API Key 的搜索请求始终不跟随重定向。

Trafilatura 在线程中保留链接与表格、去除评论；lxml 提取页面真实可见的登录、验证码、订阅等限制线索，另附到精炼输入，防止正文提取丢掉必要限制。页面有“登录”入口本身不等于无正文。

精炼使用普通 Chat Completions，不强制服务端 `response_format/json_schema`。提示词要求输出 `evidence/reasoning/type/result/selected_images`，本地严格校验；`type=content` 才能发布正文，`no_content` 是正常的无正文结果，返回具体原因且不消耗主助手的连续调用纠错次数。只保留与 focus 相关且能明确归属的信息及条件，不补写外部事实，不混淆主商品和推荐商品。最多 3 次模型输出校验尝试；纠错只加入最小固定反馈，不把失败 JSON、半成品或原生推理重新注入。网络故障不自动重放生成。

### 正常无正文与友好提示

网页子图区分 `success`（有正文）、`no_content`（正常取得无正文结论）和 `error`（执行故障）。HTTP 401/403/451 的登录、验证或授权限制，404/410 的失效链接，空响应、无可提取正文、非 HTML 响应，以及精炼模型确认无相关正文，均返回 `no_content` 和友好说明；没有正文或图片，也没有 `error_code/failed_stage` 错误标记。不根据出现“登录”入口就认定正文不可用。

网页工具将该业务结果作为 `ToolExecutionResult.status=succeeded` 提交，模型可见 `status=no_content`、`has_content=false`、来源标识及独立提示；使用普通内容，不创建正文/图片页面，不缓存空正文，不推进阅读游标。连续遇到多个无正文来源后，模型仍可正常换来源或通过最终输出向用户说明缺口。用户公开答复由主助手生成，不由工具擅自发布。

无正文回执另返回 `reason`（本次具体原因）与 `no_content_count`（当前页面连续无正文次数），视觉提示也显示该次数。按当前任务及页面 URL 计数，优先使用最终跳转地址，忽略 URL fragment；同一页面的不同来源标识、不同关注点共享计数，其他页面独立。仅工具结果成功提交后累计，成功取得并提交正文时清零；未提交、取消或任务结束后的迟到结果不累计。任务结束释放计数，不从历史记录重建或跨任务共享。

首次无正文只返回友好提示；同页连续第 2 次及之后，通过现有 `system_guidence` 追加一条 `action_guidance`，经统一构造器生成独立操作提示，随正常工具结果提交后进入下一次模型请求。提示根据原因引导模型调整关注点或查看其他页面；同页换关注点仍无有效信息时应转向其他来源，登录/验证码/授权限制优先换公开来源，资料不足则说明缺口并正常收尾。该计数只用于建议，不标记调用失败或强制终止。操作提示使用程序文案和已验证的次数，不将网页内容、页面名称或精炼模型的原因说明提升为系统操作要求。

提示采用以下明显分层，原因逐行引用，避免被当成网页原文或事实证据：

```text
════════════ 网页读取提示 ════════════

结果：未获取到可用正文
当前页面连续无正文：1 次
【注意】以下是读取情况说明，不是网页正文，不能作为来源内容引用。

网页：示例网页
链接：https://example.org/article

原因说明（非正文）：
> 该网页需要验证，暂时无法读取正文。

下一步：可以尝试其他来源；若资料仍不足，请向用户说明限制，不推断相关信息不存在。

════════════ 提示结束 ════════════
```

参数非法、来源引用失效、网络超时、HTTP 429/5xx、解析故障及模型输出不符合契约仍为执行失败，不伪装成无正文成功。全局 Core 错误上限不变；此次只修正正常业务结果的分类，未读取的正文和半成品仍不得进入页面或工作区。

[无正文回归测试](../../../../tests/test_web_page_no_content.py)验证访问限制、失效页面、空内容和非 HTML、精炼无正文、严格结果边界、真实 Core 连续三次无正文后正常收尾，以及有效正文继续分页和网络/服务故障仍失败。2026-10-26 专项 7 项通过；全量 143 项中 132 项通过、11 项独立数据库测试跳过。全部使用隔离 HTTP/模型及内存状态，未重放真实用户任务；既有任务历史保持原状，运行服务需要加载新代码后生效。

同日增加同页计数与操作提示后，专项扩至 10 项通过，全量 146 项中 135 项通过、11 项数据库测试跳过。补充检查同页不同关注点/来源别名累计、其他页面独立、成功正文提交后清零、未提交与迟到结果不累计、任务结束释放，以及第 2 次后真实模型请求收到独立操作提示。[真实模型效果验证](../../../../experiment/web-no-content-live/20261026-count-guidance/analysis.md)使用真实 MLLM 和本地可控 HTTP 合成页面，观察到计数 1/2、第二次追加提示、模型切换备选页面并正常回答，完整耗时约 54 秒；这不是任意公网网站可读性或自由规划效果的普遍保证。

每次阅读语义判断与精炼的完整原生响应、推理、验证结果与失败/取消记录保存到当前节点 `question_node_generations.payload`，`purpose=web_page_refinement`；不需要 SQL 迁移。生成状态 complete 表示收到了完整原生消息，业务是否接受另见私有事件 `accepted`。不采用窗口截断，不因正文 LRU 驱逐而删除这些记录。公开树及 SSE 不暴露私有生成。

## 原文保留与显式摘要

[内部提示词](../../../../app/agent/core/subgraph/web_page/prompt.py)采用“半精炼”：去除网页噪声、筛选阅读范围，默认保留选中内容的原语言、原句、顺序及必要上下文。中文 focus 不代表要求中文输出；普通查询不再默认翻译或写成回答式概述。

| 阅读需求 | focus 示例 | 期望处理 |
| --- | --- | --- |
| 局部查询 | `查看主商品的规格和退款限制，排除推荐商品` | 摘取相关原文及前提、例外、单位、适用范围，排除其他商品。 |
| 全文保留 | `保留全部正文、表格、代码、脚注及参考文献，保持原文，不翻译、不概括` | 判断为 original 后直接复制已提取正文，不再调用精炼，不改写、翻译或重新生成正文。 |
| 摘要 | `用中文概括申请条件，保留所有例外` | 按明确要求概括，保留对象归属、数值、否定和比较方向。 |
| 翻译 | `将退款条款完整翻译为中文，不概括` | 仅转换指定范围的语言，不擅自缩写。 |

“尽可能保留原文”也可进入原文路径；“只看训练章节，保留英文原句”仍需精炼筛选。“全文翻译”“全文总结”进入精炼，不按“全文”关键词简单放行；中文提问或“不翻译”本身不代表需要整篇原文。判断依据是调用中的阅读语义，不根据正文长度擅自改变需求。

原文路径不让模型复述正文，直接复用提取结果并按原顺序分页。访问提示独立放入 `hint`，不拼进作者正文；无可用文字时明确失败，即使存在图片也不伪造全文成功。图片按提取/去重后的页面顺序保留，沿用 `AGENT_WEB_IMAGE_MAX_SELECTED`；超出时明确提示，未经过模型相关性筛选。图片下载失败不丢弃可用文字，保留读取限制；分页、可折叠引用、LRU、任务结束释放及权限复查均复用原链路。

这里“原文”指 Trafilatura 实际提取的文字，不保证还原所有 DOM、动态内容、付费内容或 PDF；有非空提取结果也不意味着已确认页面完整可读。直出绕过的是精炼生成预算，不绕过抓取字节上限、图片预算、主模型上下文容量和资料的非可信边界。

精炼路径保留现有 `evidence/reasoning/type/result/selected_images` 输出与严格校验。字段、图片编号和正常结束可本地校验，但不能证明摘要或翻译没有语义错误；`finish_reason=length` 继续拒绝发布。原文意图判断失败而回退精炼时，长文仍可能受模型生成预算限制，不能宣称所有请求都能保证全文输出。

## 网页图片筛选与任务内存

图片提取与下载见 [image.py](../../../../app/agent/core/subgraph/web_page/image.py)。从 article/main（不存在时回退页面）中的 img 提取 src、常见懒加载地址与 srcset 候选，保留 figcaption、alt 和附近正文；过滤导航、明显广告/图标、极小图及重复 URL。下载后再按规范化图像内容去重。不是独立图片搜索，不执行 JavaScript，也不截取整页；CSS 背景图、SVG、动态 GIF/WebP 和必须登录的图片本轮不支持。

每页默认最多读取 6 张候选、保留 3 张；每张下载及标准化后不超过 4 MiB，源图最多 1600 万像素，最短边至少 48 像素；图像按 EXIF 方向处理、透明区域置白、最长边缩至 1280 像素并转换为 PNG。整个图片读取阶段上限 15 秒。数量、大小受限，因此不能声称已看完网页的所有图片或精确辨认缩小后不清晰的细节。

仅接受无账号密码的公开 HTTP/HTTPS 图像地址及常用端口。DNS 必须解析为公网地址；连接固定已校验 IP，HTTPS 使用原域名 SNI/证书校验，逐次重定向重复检查，最多 3 次重定向。图片请求不携带应用身份，不使用环境代理，不跨请求或重定向传递 Cookie；HTTP 类型声明和 Pillow 实际解码都必须通过。

图片 DNS 由 [public_dns.py](../../../../app/infrastructure/public_dns.py) 适配。正常公网解析沿用系统 DNS；只有域名的系统解析结果全部落入 `198.18.0.0/15` 时，使用固定 HTTPS 地址 `https://1.1.1.1/dns-query` 补做公开 A 记录解析，兼容 Clash 等代理的 Fake-IP 模式。采用 [Cloudflare DNS JSON 契约](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)，校验查询身份、状态、完整性及所有返回地址；5 秒时限计入原有图片阶段总时限，响应最多 64 KiB，不跟随重定向、不带凭据或环境代理。此时图片域名会发送至 Cloudflare 公共解析器，正常系统解析不新增该请求。

补解析结果仍必须全部为公网 IP，随后固定真实 IP 连接并保留原域名 Host/TLS SNI；不会直接连接或放行 Fake-IP。URL 直接写内网/Fake-IP、DNS 混入回环或私网地址、补解析失败或返回私网地址时仍拒绝，不降级为未经校验的域名请求。已校验地址只在本次图片下载中按域名及端口复用，避免同源多图重复查询，任务外不缓存。该适配只作用于网页图片，不修改系统 DNS、VPN、网页 HTML 请求或其他组件配置。

精炼模型接收正文和候选图片的原生 image_url 内容块，按 focus 选择相关图表、结构图或细节图。selected_images 只能选择本次实际提供的整数编号，拒绝布尔值、字符串、重复编号、虚构编号、超出保留数及 no_content 带图。模型输出异常沿用最多 3 次纠错，失败输出只保存在私有审计，后续精炼输入不携带失败 JSON。无图时使用纯文字输入；图片失败但正文可用时仍返回正文，并明确图片未核实。

open_web_page 的第一页同时返回正文和筛选后的图片引用；主模型直接看到真实图像及网页来源、图注，工具回执不包含 Base64。图片与正文分别声明媒体类型，共享原生分词/生成输入及 AGENT_PAGE_DISPLAY_ROUNDS 展示窗口，翻到后续文字页不重复展示图片，重看第 1 页会生成新的展示引用。依赖的 MLLM 必须支持图像 Chat Completions。

图片字节及带图片快照只驻留本次问答内存：完成、取消、失败、改变方向结束旧任务、树释放或停机均清理；同树并发任务通过独立作用域隔离，迟到响应不能恢复已经释放的图片。图片会随网页 LRU 提前释放，此时展示层明确标记当前不可读，不伪造图像也不中断其他资料展示。纯文字网页缓存继续沿用既有树级生命周期。下一任务需使用 source_id 和 focus 重新读取图片，不恢复旧图像快照。

不新增数据库表、文件资源路由或图片附件，不写 data/user/upload-file，不把输入图片字节写进原生生成审计。模型生成的图像观察文字、精炼结果和已提交的轻量工具引用仍按既有节点记录规则保存；“释放图片”不删除这些已生成文字。前端不接收网页图片文件或图片流。

## 分页、LRU 与折叠

每棵用户树分别维护搜索结果池和正文池；带图片的网页快照另绑定当前任务，退出本轮租约即释放。同一链接换 focus 后不得复用旧处理结果；当前不建立第二套原始 HTML 缓存。正文按最终文本连续切片分页，顺序拼接可恢复完整结果正文，不擅自缩短。

| 资源 | 默认容量/分页 | 驱逐后的行为 |
| --- | --- | --- |
| 搜索结果池 | 10 个查询，每页 5 条 | 来源映射随结果集释放；需重新搜索。 |
| 网页正文池 | 10 个 `(source_id, focus)`，每页 3000 字符 | 来源仍有效时可指定 focus 重新读取，否则需重新搜索。 |
| 用户树宿主 | 32 棵用户树 | 仅 LRU 驱逐没有活动任务的宿主；全部在用则明确失败。 |

[WebSessions](../../../../app/agent/core/web.py)在每轮任务持有租约，防止执行中被另一棵树驱逐。删除树先等待生产者结束，再清理两类资源；停机同样先取消/等待生产者，再释放缓存。驱逐后的迟到响应不能重新写入已关闭资源。同树跨节点可以读取仍驻留的纯文字结果，图片及其图文快照不跨任务继承，不能跨用户或跨树使用来源标识；进程重启后标识过期，不伪装恢复成功。

搜索页、正文页与选中图片均为 `foldable`，正文和图片只在页面解析时注入模型，权威工具回执只保存引用与轻量元数据。沿用 `AGENT_PAGE_DISPLAY_ROUNDS`，默认 5 次完整主模型响应后自动折叠，不是最多 5 个页面。

适配当前 Core 的两个必要点：每次重新打开都生成独立展示标识，避免重新打开同页被误判为重复；分页游标经 `ToolExecution.after_commit` 在节点权威提交成功后推进，数据库失败不跳页。签名绑定资源、位置和展示标识，可检查篡改与跨会话引用，无需积累无界的引用表。

候选数和保留数可按需要设置为 30/20 等更大值；运行时使用配置值，不静默截断到原有 20/6 张校验上限。配置在 Agent 装配时加载，已有实例不会热更新。数量增加不等于所有图片必然读取：格式、单图大小、15 秒总下载时限与相关性筛选仍生效。

所有已暴露的 `AGENT_*` LRU 容量、分页大小、正文展示轮次、并发和图片预算均以配置为准，只校验正整数，不另加固定最大值。默认值只在未配置时使用；实际不足一页时返回剩余内容，不补足到配置数量。记忆单次召回的 Top-20 是独立检索契约，不是分页大小校验上限。

搜索请求精确为 `POST /v1/tools/search`，body 为 `query/count/need_content:false`；已有 base URL 以 `/v1` 结尾时不重复拼接。缺少 Key 不发送请求；搜索服务有界并发、取消释放额度、不自动重试。配置修改后重启服务。
