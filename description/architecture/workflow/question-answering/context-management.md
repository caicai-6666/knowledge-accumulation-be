# 树状上下文与工作区管理

## 选择节点后的注入

[QuestionAgentService](../../../../app/service/question_agent.py)通过节点仓库在同一一致性事务内读取树归属、所选路径、公开正文、中途输出及所选工作区。不会载入其他分支，也不会为了构造模型上下文加载所有原生生成。

`exploration` 非空树由调用方显式选择节点；`assistant` 生成不接受 `selected_node_id`，专用记忆加载路径选取 `main_leaf_id` 并读取持久化压缩边界和当前工作区。两者的空树首次生成均没有父节点。加载后得到的实际起点统一用于历史注入、快照、任务前摘要的覆盖终点以及成功/失败任务落盘，避免助理自动选择后仍把新任务当作根节点。底层树结构共用，但助理只允许专用路径线性追加；通用追加和结束入口拒绝助理树，详见[助理记忆](assistant-memory.md)。

探索节点 `path_type` 只用于归属校验，不改变上下文搜索；摘要与任务都可位于主干或分支。树类型、路径类型、主干指针和节点标识只留在程序状态，不注入模型。并发读取后主干变化仍由提交时的树行锁与 `revision` 冲突拒绝，不隐式更换起点。

树公开投影由 `app.agent.context.build_tree_context` 共用，模式专属资料在该投影之后装配。助理个人背景与偏好只进入本轮补充资料，不自动写入工作区；每次按可信用户加载，任务前压缩后仍保留。模式包、来源与状态契约见[助理与探索模式](agent-modes.md#上下文与提示词)。

以下选点与分支示例适用于探索树；助理的当前摘要、窗口边界和工作区按[助理记忆契约](assistant-memory.md)持久化。

从所选节点向根查找首个结构摘要，以该摘要及其后的任务构建有效路径；随后顺序应用路径内已提交的部分前缀摘要检查点，最终注入最近有效摘要与未被覆盖的任务。完整任务包含问题和已接受的原生工具对；没有原生工具对时使用已保存的中途输出和最终答案。消息角色、边界和去重见[上下文渲染](context-rendering.md)。不把失败工具调用、私有推理和旧工作区副本拼入历史。generating 节点不能作为起点；其他终态可用于显式新问题，按[生命周期规则](node-lifecycle.md#消息私有生成与上下文)保留问题、业务结束标记及允许的已接受输出，不把半成品当作最终答案，也不重新激活原任务。

拓扑为 S1 → C → D → S2 → E 时：

- 选择 D：注入 S1、C、D，恢复 D 的工作区。
- 选择 E：注入 S2、E，恢复 E 的工作区。
- 从 D 新提问 H，若任务前整理覆盖 C、D 全部完整任务：创建新的 S3 → H，S3 的父节点为 D，H 的父节点为 S3；不复用或修改 S2。若只选中 C，则在 H 内记录覆盖 C 的摘要检查点，保留 D 的完整历史，不创建声称覆盖 D 的结构摘要节点。

任务前摘要、任务本身、初始提问和快照引用在同一事务提交。摘要覆盖起点必须是 D 当前有效上下文的第一个节点，终点必须是 D；完成摘要不会改变先前节点的工作区或正文。摘要生成本身的私有响应保存在新任务的生成记录中，模型可见摘要仅含业务文字。

## 四区域工作区

[WorkspacePayload](../../../../app/agent/core/workspace.py)沿用参考项目的四区域设计：

| 区域 | 含义 |
| --- | --- |
| task_constraints | 本次用户任务与明确补充，不能混入助手自己的计划。 |
| known_information | 精简事实、来源和 confirmed/user_reported/unverified/conflicted 状态。 |
| remaining_directions | 尚需尝试的计划。 |
| explored_directions | 已尝试计划、succeeded/failed/inconclusive 结果、结论和信息引用。 |

confirmed 必须有来源；同一方向不能同时处于两个方向区域；引用不能重复或悬空。新增普通条目由程序生成稳定业务键，探索完成保留已有方向键并原子转移。所有修改先在深拷贝中预演，完整验收后提交；探索保存工作区版本，助理更新每树唯一的当前工作区。

根节点空 JSON 可转换为空四区；其他任意旧 JSON 形状明确拒绝，不从旧记录猜测事实。探索新任务恢复选中快照，助理新任务读取当前工作区，当前 task 更新为本次问题，已有事实和补充保留。历史任务内容仍保留在其原节点。

## 预算与压缩

主题摘要采用[增量规划、并行总结与完整汇总](topic-summary.md)，不再由单次工具同时产生摘要和工作区。工作区达到自身预算时独立精简；整理有效历史时两个结果全部验收后提交。因工作区操作溢出而触发的整理只处理工作区，不重复生成主题摘要。

固定输入使用实际系统提示词、工具定义和空动态消息外壳进行聊天分词，扣除生成上限及管理预留后按 3:7 分配工作区与轨迹。累计摘要的实际渲染 token 从轨迹区扣除，余量才是 FIFO 配额，不向工作区借用容量。逐任务与摘要使用 vLLM 纯文本分词；完整请求另用真实聊天模板、工具、当前思考强度和驻留图片校验硬上限。测试可以注入确定性计数器，生产不按字符估算。

[FIFO 管理](../../../../app/agent/core/context_budget/fifo.py)只读取当前所选祖先链：

1. 每个已封闭历史任务独立渲染、计数，保留任务结束语义；取消、失败和调整方向也属于封闭任务，不意味着业务成功。当前任务及其全部已接受交互作为最后一个活动任务。
2. 从最早任务累计至总 FIFO token 的70%所在任务，向右对齐完整任务边界；若落到活动任务，回退到最后一个完整历史任务。没有合法前缀时不摘要活动任务，也不静默驱逐它。
3. 使用量达到80%时提示先将该范围内必要事实保存至工作区；达到95%即触发整理，向模型明确实际95%阈值，不伪称已使用100%。生成前及待执行工具前校验，满容量先整理历史；工具结果和提示也计数，执行后达到实际配额立即整理，否则下轮先整理。
4. 摘要只接收旧累计摘要和选定完整前缀。剩余历史、当前用户问题、附件、上下文资料、活动工具对与图片展示机会均保留。新摘要重新扣减轨迹预算，保留提示后仍达95%则拒绝候选。
5. 成功工具不会因后续容量失败而回滚或重放。无合法范围、分词异常、摘要验收失败或完整请求超出硬上限时明确停止。容量提示不暴露数据库节点ID；阈值和可执行的整理动作须准确说明。

探索任务前只有选择了整条有效历史，才按原事务规则创建结构摘要节点。部分前缀及运行内整理在本任务 `exchanges` 中保存 `context_summary`，新增 `covered_turns` 表示相对于当时有效祖先任务列表的覆盖数量；树恢复按检查点发生顺序消费前缀，再加入该节点自身完整任务。此字段只用于持久化投影，不进入模型材料；超出可用祖先范围时拒绝。旧的无覆盖字段检查点不能证明祖先覆盖，仍仅作原运行的审计。原始节点、完整工具轨迹和私有生成均保留，不修改其他分支，不新增SQL列。

工作区操作预演达到100%时，冻结预演位置和新增ID，保护旧目标及关联信息，先整理旧副本至严格低于70%，再应用同一次修改；最终须严格低于80%。超过80%但未达到100%时提交合法修改并提醒主动整理。副本整理明确拒绝可进入有限纠错，依赖与提交故障仍停止，详见[多轮工作区精简](workspace-compression.md)。

工作区精简使用受控增删改工具，允许精简有效要求、合并重复信息、调整引用并删除冗余条目；保护路径必须原样保留，既有信息确认状态和探索结果不可改变，不新增探索成果。保留必要事实、来源定位与条件属于模型语义约束，结构保护不能自动证明自然语言等价。

整理完成后保留本轮全部已接受工具对作为继续点，避免模型因看不到回执而重复整理。连续纠错期间不通过自动整理偷偷删除失败反馈，完整动作成功后才清理。单条输入或压缩材料本身超出硬上限时明确失败，不静默截断或伪造摘要；超大历史的多段分层压缩不在本阶段实现。

## 持久化与后续范围

公开提问、中途和最终输出仍与 pending 记忆登记共事务；摘要整理本身不调用 Embedding 或检索业务工具。完整原生推理持续保存，无窗口，但不自动重注入模型。

工作区和上下文压缩、原生生成记录均通过现有 NodeJournal 与节点仓库接入。不自动执行迁移、不改变实际配置，不新增门户、管理员或资料维护路由。进程崩溃后的自动重放、跨实例任务抢占和超大上下文分段压缩仍不在本模块范围；HTTP/SSE 沿用探索会话宿主。
