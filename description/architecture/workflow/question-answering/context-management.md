# 树状上下文与工作区管理

## 选择节点后的注入

[QuestionAgentService](../../../../app/service/question_agent.py)通过节点仓库在同一一致性事务内读取树归属、所选路径、公开正文、中途输出及所选工作区。不会载入其他分支，也不会为了构造模型上下文加载所有原生生成。

`exploration` 非空树由调用方显式选择节点；`assistant` 生成不接受 `selected_node_id`，同一加载器自动选取 `main_leaf_id`。两者的空树首次生成均没有父节点。加载后得到的实际起点统一用于历史注入、快照、任务前摘要的覆盖终点以及成功/失败任务落盘，避免助理自动选择后仍把新任务当作根节点。底层历史读取与结构存储共用，不对助理树额外禁止分支。

节点 `path_type` 只用于归属校验，不改变上下文搜索；摘要与任务都可位于主干或分支。树类型、路径类型、主干指针和节点标识只留在程序状态，不注入模型。并发读取后主干变化仍由提交时的树行锁与 `revision` 冲突拒绝，不隐式更换起点。

树公开投影由 `app.agent.context.build_tree_context` 共用，模式专属资料在该投影之后装配。助理个人背景与偏好只进入本轮补充资料，不自动写入工作区；每次按可信用户加载，任务前压缩后仍保留。模式包、来源与状态契约见[助理与探索模式](agent-modes.md#上下文与提示词)。

严格遵循：从所选节点向根查找首个摘要，只注入该摘要及其后的任务。完整任务包含问题和已接受的原生工具对；没有原生工具对时使用已保存的中途输出和最终答案。消息角色、边界和去重见[上下文渲染](context-rendering.md)。不把失败工具调用、私有推理和旧工作区副本拼入历史。generating 节点不能作为起点；其他终态可用于显式新问题，按[生命周期规则](node-lifecycle.md#消息私有生成与上下文)保留问题、业务结束标记及允许的已接受输出，不把半成品当作最终答案，也不重新激活原任务。

拓扑为 S1 → C → D → S2 → E 时：

- 选择 D：注入 S1、C、D，恢复 D 的工作区。
- 选择 E：注入 S2、E，恢复 E 的工作区。
- 从 D 新提问 H 若触发摘要：创建新的 S3 → H，S3 的父节点为 D，H 的父节点为 S3；不复用或修改 S2。

任务前摘要、任务本身、初始提问和快照引用在同一事务提交。摘要覆盖起点必须是 D 当前有效上下文的第一个节点，终点必须是 D；完成摘要不会改变先前节点的工作区或正文。摘要生成本身的私有响应保存在新任务的生成记录中，模型可见摘要仅含业务文字。

## 四区域工作区

[WorkspacePayload](../../../../app/agent/core/workspace.py)沿用参考项目的四区域设计：

| 区域 | 含义 |
| --- | --- |
| task_constraints | 本次用户任务与明确补充，不能混入助手自己的计划。 |
| known_information | 精简事实、来源和 confirmed/user_reported/unverified/conflicted 状态。 |
| remaining_directions | 尚需尝试的计划。 |
| explored_directions | 已尝试计划、succeeded/failed/inconclusive 结果、结论和信息引用。 |

confirmed 必须有来源；同一方向不能同时处于两个方向区域；引用不能重复或悬空。新增普通条目由程序生成稳定业务键，探索完成保留已有方向键并原子转移。所有修改先在深拷贝中预演，完整验收后提交新工作区版本。

根节点空 JSON 可转换为空四区；其他任意旧 JSON 形状明确拒绝，不从旧记录猜测事实。每个新任务恢复选中快照，当前 task 更新为本次问题，已有事实和补充保留。历史任务内容仍保留在其原节点。

## 预算与压缩

全部计数使用已有 vLLM 原生聊天分词器，包含实际工具、模板及本次思考强度；测试可显式注入确定性替身，生产默认不按字符估算。先扣固定输入、生成上限和管理预留，再按 3:7 分配工作区与轨迹参考预算。

完整请求接近软阈值时先整理；候选工作区达到配额时先保护本次修改目标，再压缩候选，验收结果低于工作区和摘要目标容量约 70%。硬上限始终包含输出与管理预留，计数异常或整理仍不足时停止，不发送超预算生成。

自动任务前整理把完整有效历史压缩成新树摘要。当前任务内整理只更新本次有效投影并在 exchanges 追加 context_summary 检查点，保留完整旧轨迹和原生生成；不会修改旧摘要或在生成中重写树拓扑。当前问题和补充材料始终单独注入，不因摘要被静默删除。

压缩严格保留用户任务和补充原文、各区域条目键集合、来源、确认状态、探索结果及引用，只精简事实正文、计划和结论；本次修改的目标条目保持不变。模型语义保真仍需样本评估，结构保护不等于自动证明语义等价。

整理完成后保留本次成功工具对作为继续点，避免模型因看不到回执而重复整理。连续纠错期间不通过自动整理偷偷删除失败反馈，完整动作成功后才清理。单条输入或压缩材料本身超出硬上限时明确失败，不静默截断或伪造摘要；超大历史的多段分层压缩不在本阶段实现。

## 持久化与后续范围

公开提问、中途和最终输出仍与 pending 记忆登记共事务；本阶段不自动调用 Embedding、刷新检索缓存或提供检索工具。完整原生推理持续保存，无窗口，但不自动重注入模型。

工作区和上下文压缩、原生生成记录均通过现有 NodeJournal 与节点仓库接入。不自动执行迁移、不改变实际配置，不新增门户、管理员或资料维护路由。进程崩溃后的自动重放、跨实例任务抢占、HTTP/SSE 和超大上下文分段压缩后续独立设计。
