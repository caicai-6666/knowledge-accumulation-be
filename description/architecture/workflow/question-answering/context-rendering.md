# Core 上下文渲染与消息组织

## 用途与来源

将 contract-service-be 的工作区、任务输入、摘要区和原生消息组织方式接入本项目 Core。模型读取独立的 user、assistant、tool 消息，不再把历史问答、当前问题和工作区合成一条 user 文本。

本专题维护展示与消息契约；节点选择、摘要生成和容量规则见[树状上下文管理](context-management.md)。完整可读样例见[实际消息展示](../../../../tests/fixtures/core-rendering/messages.md)，对应[原始消息数组](../../../../tests/fixtures/core-rendering/messages.json)只用于检查实际请求，不作为整体 user 消息注入。

---

## 消息顺序

[build_messages](../../../../app/agent/core/context_rendering/messages.py) 按以下顺序装配：

| 顺序 | 角色与内容 |
| --- | --- |
| 1 | system：当前模式角色、公司背景、平台协作、交互及工作区规则。 |
| 2 | user：最近树摘要；不存在时省略。 |
| 3 | 逐轮历史：user 任务输入 → 已接受的 assistant/tool 工具对或真实助手正文 → user 结束记录。 |
| 4 | user：当前工作区，紧邻本轮任务。 |
| 5 | user：本轮问题、附件引用、内部调用方提供的上下文资料和可信平台等级。 |
| 6 | 本轮已接受的原生 assistant/tool 对。 |
| 7 | 连续纠错期间的临时反馈；成功提交后清除。 |

摘要后仍按同一入口重建消息。固定预算仅使用系统、工具和空动态消息外壳；本轮任务文本计入FIFO动态区；工作区容量、整理结果验收与正式生成使用相同的 YAML 展示文本。计数仍使用实际模型分词接口。

## 工作区和任务展示

[工作区渲染器](../../../../app/agent/core/context_rendering/workspace.py) 移植参考实现：中文区域标题、`/task_constraints` 等真实路径、按原顺序排列的 YAML 和明确结束边界。空区域及空任务补充省略；全空时只显示“当前工作区为空。”。条目内的 `source: null`、空引用列表、真实稳定键和多行正文保持不变；不递归删掉业务字段。

多行文字采用 YAML 块样式，类型歧义由安全序列化器处理。自定义 Dumper 只在本渲染器生效，不修改 PyYAML 全局规则。展示夹具见[工作区样例](../../../../tests/fixtures/core-rendering/workspace.md)，已与参考项目对同一输入的结果逐字比对。

[任务渲染器](../../../../app/agent/core/context_rendering/task.py) 沿用“任务 → 用户输入 → 用户问题”的标题结构。正文和内部上下文资料使用 text 围栏，可信平台等级使用 YAML；围栏长度始终超过正文中的连续反引号，资料不能提前关闭所属区域。没有提供的资料和权限不生成占位，不推断额外平台等级。

任务展示序号仅表示本次上下文的阅读顺序。按本项目规范，不注入原项目的持久化任务 ID、节点/树 ID、版本或内部编排信息。原生调用 ID 与工作区业务键保留，因为它们用于真实工具配对和路径定位。

## 任务时间与相对日期

任务头部显示 `任务创建时间：2026-09-16T00:30:00.123+08:00（北京时间）`，作为模型理解相对日期所需的业务基准，不是工程追踪标识。

- 当前任务：`AgentInput.created_at` 接收带时区的时间。独立 Core 输入创建时默认采集一次 UTC 时间；正式 `QuestionAgentService` 在模型执行前绑定仓库返回的节点 `created_at`，预登记任务再次激活也保留原时间，不使用激活时间。
- 历史任务：`build_tree_context` 从各自节点取创建时间，写入 `HistoryTurn.created_at`，每轮单独渲染为固定 UTC+08:00，避免服务端时区影响展示。手工构造的旧历史缺少时间时省略，不猜成当前时间。
- 相对日期：当前问题中的“今天、昨天、上周”以当前任务时间为准；历史问题以各自任务时间为准。“昨天”为前一自然日，“上周”为上一周周一至周日。用户明确指定日期、时区或参照时刻时优先使用其约定。
- 运算：精确日期增减由 [calculate_date](agent-core.md#日期计算工具) 完成；任务时间不能充当业务事件发生时间。
- 整理：历史结构化资料保留带时区的创建时间，当前活动任务不参与主题整理。整理提示词要求保留必要时间基准或有依据的绝对日期，不把旧任务中的相对时间移到今天。此项属于模型语义约束，不能保证自由文本摘要绝无日期解释错误。

动态FIFO计数、正式生成和整理后重建复用同一个任务时间。原数据库已经保存节点创建时间，本次不新增SQL字段、前端参数或配置。需要此刻时间时可调用 [get_current_time](agent-core.md#当前时间工具)，每次执行读取系统时钟；任务头部时间不会自动刷新，重启/历史恢复不会把原任务时间改成恢复时刻。已经生成且丢失日期依据的旧摘要不会被补造或自动重写。

## 当前任务附件

公共 Core 的 `AttachmentReference` 只定义 `type` 与 `file_id`；`AgentInput.attachments` 默认空列表，内部 `QuestionAgentService.generate(attachments=..., uploads=...)` 接入同一入口。`type` 接受 `images`（多图）、`audio`（音频）、`video`（视频），不使用文件扩展名或 MIME 类型；文件 ID 为完整小写、带连字符 UUID。

用户上传文件保存于项目根目录下的 `data/user/upload-file/`，由 `.gitignore` 排除。类型决定固定后缀，UUID 与任务正文登记共同用于定位和鉴权，完整契约见[用户附件引用与文件定位](../../data/question-file.md)。模型上下文只显示引用，不显示服务器存储路径。内部保存和读取已实现，图像附件可通过[独立图像工具](image-reading.md)逐页查看；探索 HTTP 已接入 multipart PDF 上传；音频/视频查看尚未接入。测试文件仍使用 `tests/fixtures/` 或 `tests/tmp/`。

[附件渲染器](../../../../app/agent/core/context_rendering/attachment.py) 在当前问题之后展示“用户附件”。每项仅显示文件类型和文件 ID，保留输入顺序；不添加文件名、摘要、补充说明、查看工具名或使用方法。空附件不生成区域，未定义字段与非法类型在生成前拒绝；替代旧任务时，也先校验附件再执行停止操作。

以下是模型实际读取的附件区域：

```yaml
- 文件类型: 多图
  文件ID: 11111111-1111-4111-8111-111111111111
- 文件类型: 音频
  文件ID: 22222222-2222-4222-8222-222222222222
- 文件类型: 视频
  文件ID: 33333333-3333-4333-8333-333333333333
```

附件使用与其他区域一致的安全 YAML 和自适应围栏，仅作为 user 资料。动态FIFO计数、实际生成、多轮重建及摘要后继续均读取同一份当前附件。任务附件已持久化，历史渲染恢复各任务自己的引用，不把当前附件补入其他历史任务；文件保存与归属读取由宿主文件服务处理，Core 渲染器不访问磁盘。

## 历史原生消息与落盘适配

[build_tree_context](../../../../app/agent/context.py) 从已经选定的路径读取 TaskContent.exchanges，填入 HistoryTurn.native_messages。继续使用已有 JSON 正文，无需新增表、列、启动任务或第二份缓存。

[原生消息校验](../../../../app/agent/core/native_messages.py) 沿用参考项目契约：每条 assistant 恰有一个工具调用；反馈必须紧邻并匹配；调用标识不能重复；参数必须是无重复键、无非法数值的 JSON 对象。模型随工具调用附带的普通文本和私有推理不能混入已接受的 assistant 消息；tool 回执允许程序渲染的可读文本，具体格式见[工具返回契约](tool-content-contract.md#执行结果与失败边界)。已接受的参数字符串、工具名称和回执按提交结果恢复，不从公开输出重建参数。输出工具若注册执行后钩子，先转换再提交；助理已接受的 `finish_task.content` 为转换后的正文，原始生成仅保存在私有审计，见[正文转换](assistant-message-rendering.md)。

历史封闭时去除已完成任务的程序操作提示，但不按正文关键字删除资料。context_summary 是宿主保存的整理检查点，带 covered_turns 的新检查点先应用祖先覆盖投影，随后从原生消息中排除，不能用它掩盖一半的工具调用。原始完整 exchanges 保留在数据库；需要进一步缩短历史时仍由树摘要和容量规则处理。

若调用方只提供明确的公开历史，没有原生工具对，则中途和最终正文作为真实 assistant 消息展示；不猜测工具调用。已经存在 finish_task 时不重复追加同一答案。

延续本项目终态边界：非成功任务不注入最终正文或 finish_task 工具对；cancelled 另排除中途正文及 emit_progress 对。已接受的其他工具和必要阶段信息按状态保留，并独立展示“用户终止 / 用户调整方向 / 执行失败”的程序记录。记录不是新的用户请求，不会执行历史工具。

## 本项目的数据边界

已移植参考项目的[主题发现与总结](topic-summary.md)，按选中路径而非线性 FIFO 提供资料。内部结构继续由 SummaryContent.text 承载；模型注入及打开树的公开 text 显示主题、当前记忆、未决事项与业务出处，隐藏编码和来源标签。历史纯文本保持原样展示，不在展示阶段重新生成摘要。

探索从选定节点回溯摘要及其后的有效路径，恢复选定工作区快照；助理只读取主干的[持久化压缩窗口与当前工作区](assistant-memory.md)，不允许选择历史分支。其他分支和未来节点不注入。原生推理完整持久化、不采用窗口，但不会自动再次送入模型。

[探索 HTTP/SSE 与 PDF 上传](exploration-session.md)已接入；音频/视频查看和合同业务工具仍未接入。[公共折叠机制](tool-content-contract.md)按页面引用注入图片、文本和表格，正文只进入当前请求的临时 user 消息；历史工具轨迹保留来源及未展示占位，不自动重开资源。

## 模式专用请求提示

公共 Core 的实际请求样例不含探索开场提醒。探索工厂在正式模型请求末尾追加[开场或长执行提示](agent-modes.md#探索中途输出与沟通提醒)，计入请求预算，但不保存在历史、工作区或摘要材料中；个人助理不装配这两种提示，也不提供中途输出工具。历史中已经存在的公开中途输出仍按原有终态过滤规则恢复，本次迁移不删除历史数据。
