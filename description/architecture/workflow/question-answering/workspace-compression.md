# 多轮工作区精简

按 contract-service-be 的工作区压缩方案实现，取代一次提交完整工作区的简化版本。公共 Core 的探索和助理模式共用；[主题摘要](topic-summary.md)仍负责历史记忆，工作区整理不读取其他分支、不调用业务查询工具、不生成新的业务成果。

---

## 编辑与结束契约

压缩子 Agent 只获得以下四个工具；每轮必须且只能提交一个完整调用，不接受普通文本作为结果。

| 工具 | 用途与验收 |
| --- | --- |
| `workspace_replace` | 精简已有字段或完整条目；复用主 Core 的路径、类型和引用校验。 |
| `workspace_add` | 合并时新增必要承接条目，ID由程序分配；不能收束剩余方向或新增探索成果。 |
| `workspace_delete` | 删除确属冗余或失效的完整条目；先处理引用，不允许悬空引用。 |
| `finish_compression` | 参数只有 `summary`，简述实际整理及保留情况；不提交工作区全文，不宣称已持久化。 |

每个成功编辑后，系统反馈最新副本的实际 token 数、预算与是否达标，并将最新完整工作区单独放在下一轮末尾。已有成功编辑不重放。只有完成工具通过容量与保护校验才返回候选；初始副本已达标也必须显式完成。

提示词以参考项目文本为基础，将合同专属称谓改为原始材料，并保留本项目的任务时间基准规则。可以精简要求与来源措辞、合并重复信息及规划、删除失效或冗余条目；必须保留有效目标、关键事实、条件、争议与定位线索。语义保真属于模型约束，程序不声称能证明自然语言等价。

## 保护与状态规则

- `protected_values` 使用绝对工作区路径，值必须与输入副本一致；路径或原值不符时在模型调用前拒绝。
- 每一步及最终结果均检查保护值；字段修改、删除、整体替换祖先条目都不能绕过保护。
- `reserved_path` 是原操作已经预留的新增位置，整理期间不可占用。
- 保留的既有信息不能改变 `status`，包括升级或降级；已有探索结果不能改变 `outcome`。
- 整理不能创建新的已探索条目，也不能通过 `workspace_add` 将剩余方向收束成成果。
- 合并时先保存承接信息，再调整 `information_ids`，最后删除冗余条目；每一步都必须是合法工作区。

没有强制所有旧条目ID及文字永久不变；稳定ID在仍被使用时保留，允许通过受控编辑完成引用迁移和冗余删除。保护路径则始终原样保留。

## 预演、压缩与应用原操作

主助手工作区修改先在副本上预演，取得合法候选和程序分配的新增ID，再计算预计容量：

1. 预计使用量未超过80%：按原流程提交合法候选并返回使用量。
2. 严格超过80%但未达到100%：提交合法候选，同时提醒主助手暂停业务探索、主动整理至低于80%。
3. 达到100%：冻结预演操作，保护旧目标及关联引用，先整理**修改前**的工作区，再应用同一次操作。

第三种情况中，修改已有字段时保护整个业务条目；用户任务或补充按目标路径保护。普通新增预留程序已分配的ID。探索收束保护原剩余方向及新结果引用的已知信息。待处理新值不交给压缩模型，避免模型提前执行或改写原操作。

预算为 `B` 时，压缩副本必须满足 `tokens <= (7*B-1)//10`，即严格低于70%。随后把冻结预演中的同一位置和值应用到副本，不重新生成ID；最终必须满足 `tokens*5 < B*4`，即严格低于80%。计数使用模型原生分词接口，不按字符数估算、不按展示百分比取整判定。

原操作无法应用、引用不再合法或最终容量不达标时，不提交任何候选。工作区操作引发的压缩不触发主题总结，也不增加树摘要节点。整段上下文整理若同时需要压缩工作区，则工作区与主题总结均验收后才提交。

## 上下文、审计与失败边界

每次整理拥有独立副本、成功交互及临时纠错链；合法编辑完成后清除整段失败反馈，下一轮保留成功工具对和最新状态。普通文字、失败编辑和未验收候选不进入权威工作区。

最多32轮，连续错误上限复用 Core 的 `max_consecutive_errors`；成功编辑重置连续错误计数，容量已达标不自动结束。无变化编辑、提前完成、未知工具、多工具、截断、拒绝及不合法参数均拒绝。压缩子循环连续拒绝、轮数用尽或容量不足，以及重放后未低于80%，通过 `WorkspaceEditRejected` 明确标记候选未提交；主循环保留旧工作区并进入有界纠错，成功动作清除整个失败提示链。模型调用、分词、数据库与未知提交结果不使用该异常，直接停止，不重放外部操作。

完整响应、推理和分片仍由 Core `_invoke` 记录。单独工作区压缩使用 `workspace_compaction`；组合历史整理沿用宿主对应 purpose。原生推理不重新注入模型。取消、超时或中途失败沿用宿主清理和终态记录，已接受的临时编辑不会提前提交；私有审计按现有数据库故障与有界清理约束尽力保留。

不新增实际配置项、数据库迁移或外部接口。并发、模型时限、输出预留和分词基础设施沿用现有配置。主循环总整理次数仍受 `max_compressions` 约束。
