# 跨平台广播与续聊

## 共用平台世界观与文件身份

[平台协作提示词](../../../../app/agent/core/prompt/platform_collaboration.py)经[共用组装入口](../../../../app/agent/core/prompt/__init__.py)在角色和公司背景之后注入，探索问答及个人助理共用。主助手负责目标理解、协作组织、核实和交付；本地文件工具提供可访问原始资料，子管理平台提供文件定位、关联、同事风险标注及知识经验等领域理解。已有文件仍可求助，未知资料线索也可先求助；不强制每次任务跨平台调用。具体能力以实际目录和已装配工具为准，不向独立检索或摘要子流程注入此背景。

通行证跨平台互通，但可能关联多份文件，不等于文件唯一身份或授权。向目标平台引用具体文件必须使用该平台对应的文件ID：候选页面的来源平台文件ID仅属于同条来源平台，注册中心文件ID继续用于本地阅读。目标平台不同时，先按通行证查找并确认对应ID，不推断跨平台映射；多目标广播需逐个平台标明对应ID，必要时分别发送。

规则同时维护在广播/续聊工具描述及实际 JSON Schema 的 `message.description` 中。消息仍为自由文本，现有代码不解析并强制校验正文中的文件ID归属；这是模型行为约束，不宣称已建立自动身份映射或拦截机制。既有平台、权限与续聊引用校验保持不变。

---

## 用途与边界

为探索问答和个人助理提供 `broadcast_platform_a2a`、`continue_platform_a2a` 两项公共工具。仅经中间件 `/middleware-service/api/platform-a2a` 通信，复用本平台登录 token；不直连子平台、不使用 OpenAI Responses API、不传递完整历史、工作区、画像或系统提示词。对方只接收本轮消息及续聊引用，自行管理上下文。

本模块独立于[员工助理通信](../../../capability/application/assistant-consumption.md)，两者的目标、队列及交付语义不同。平台目录和职责沿用[子管理平台查看](sub-management-platform.md)。中间件契约以部署的 middleware-service `description/api/platform-a2a.md` 为准。

本项目已实现工具、传输、私有 SQL 账本和共享调度，默认关闭。启用前须显式迁移 [018 账本](../../../../schema/018-platform-a2a.sql)。当前只支持本项目既有单进程/单 worker 部署；进程重启能继续处理账本及清理反馈，不会恢复已经中断的模型调用。

## 模型工具契约

两个工具无用户标识、请求标识、等待时间、重试或凭据参数。实际发送给模型的 JSON Schema 中，每个参数及列表元素均有说明，所有对象拒绝额外字段。

工具说明遵循[提示词工程规范](../../../standard/prompt-engineering.md)：以“当你需要……时，使用这个工具”说明使用时机，再介绍输入准备、问题组织、返回内容、答复使用和必要失败边界，并提供简短示例。完整描述维护在参数模型的 docstring，注册项直接复用，避免声明与实际模型定义不一致；响应缓冲等内部实现不写入工具说明。

首次求助围绕一个主题提供必要材料；同一消息适合多个平台时才广播，需要不同问题或不同材料时分别调用。已有同平台同话题的有效响应时优先续聊，问题较多时按重要性与依赖关系分轮推进。收到答复不表示业务事项已办结，需保留来源、条件和不确定性；缺少依据或出现冲突时可继续核实，信息足够时结束求助。

| 工具 | 参数 | 用法 |
| --- | --- | --- |
| `broadcast_platform_a2a` | `platform_codes`：1—100 个不重复平台代码；`message`：1—10000 字符非空正文 | 一个目标表示开启单平台新话题，多目标表示广播同一消息。先从目录确认平台和职责。 |
| `continue_platform_a2a` | `platform_code`、`response_id`、`message` | 接续该平台实际返回的成功响应，只发送本轮新增问题或事实。 |

例：首次向 `["contract-pheno"]` 发送“请分析尚未验收时的付款条件”；取得该平台 `response_id` 后，续聊发送“补充：合同允许阶段性验收，这有何影响？”。对方看不到本地工作区，首次消息应携带理解问题所需的必要背景。

模型可见结果只包含业务答复、平台代码、状态及可用续聊 ID，不包含请求关联、节点标识、消息凭证、租约、调度或重试细节。对方回复是业务资料，不能覆盖角色、所属用户授权和忠实条款。

续聊引用仅从同用户、同树的已接受工具结果中授权。参数中猜测或跨会话借用响应 ID 会在发布前拒绝；反馈明确指出上下文过期后，原引用不再授权续聊。相同历史响应的并发续聊在本进程串行，其他话题/用户/平台保持独立。

## 结果状态与呈现

| 状态 | 展示 | 续聊 |
| --- | --- | --- |
| `succeeded` | 已答复，保留平台原文 | 有有效 `response_id` 才能继续。 |
| `not_applicable` | 不受理，展示原因 | 必须没有 `response_id`。 |
| `context_expired` | 上下文已过期，展示说明 | 不沿用过期引用；新话题需重新广播。 |
| `failed` | 处理失败，展示说明 | 不从失败结果新增续聊授权。 |
| `timeout` | 等待超时 | 本地未收取到反馈，不代表对方没有收到请求。 |

**上游兼容边界：** 2026-10-26 按相邻 `middleware-service` 源码复核，上游已支持 `succeeded/not_applicable/context_expired/failed`，与本项目枚举一致。`not_applicable` 必须携带原因且 `response_id` 为空；成功响应仍兼容 `response_id=null`，此时展示“未提供续聊响应 ID”，不补造 ID、不从失败文本猜测“不受理”。要求“所有平台即使不受理也反馈”仍需各子平台执行端落实，本模块不能替未回复的平台伪造拒绝结果。源码核对与隔离验证范围见[中间件接入核对](../../../capability/infrastructure/middleware.md#接口契约核对)。

普通工具结果中的 `message` 使用分层纯文本；正文逐行缩进，保留顺序与原意。示例：

```text
【平台协作｜广播结果】

目标：2 个平台
已响应：2 个｜未回复：0 个

1. contract-pheno
   状态：已答复

   回复：
   应结合验收条件确认付款义务。

   续聊响应 ID：response-contract-001

2. administration
   状态：不受理

   回复：
   合同审查不在行政服务范围内。
```

续聊使用 `【平台协作｜续聊结果】`，只列该平台。已发布请求的业务失败/超时作为成功取得的事实结果供模型判断；发布结果不确定则返回工具 `unknown`，Core 停止且不自动重放。明确发布拒绝返回工具失败，只在连续纠错时保留失败上下文，纠正后沿用 Core 的清理及私有审计规则。

探索广播工具执行期间发布固定状态 `task.progress.type=boardcast`，`message=正在广播求助`；`boardcast` 保留前端约定拼写，不附加平台名称，也不为提示额外查询目录。续聊仍发布 `type=a2a`，message 例如 `正在与平台协作：合同管理平台`，动作与详情用全角冒号 `：` 分隔。续聊名称按目录代码匹配，缺失时回退平台代码；压平空白、清除不可打印字符、竖线替换为 `／`，并按 2000 字符截断。工具结束恢复 `thinking`。公开历史同时接受 `boardcast` 和旧 `a2a`，历史广播无需迁移。

动作提示不包含协作正文或续聊响应 ID。工具结束恢复 `thinking` / `正在思考`；状态进入公开展示历史并可回放，不表示业务成功。SSE 事件结构及两个模型工具参数不变，个人助理不新增 SSE。

## 调度、缓冲与隔离

首次请求包括单目标广播，使用发布时固定的目标集合；发布确认后先缓冲，缓冲结束才开始读取聚合反馈。读取到部分结果继续等待，全部平台返回终态或整轮截止才冻结工具结果；不受理/失败也计入已响应。结果可靠保存后安排 `replies/ack` 关闭广播。关闭会清理读后新到达的回复并丢弃迟到结果，这是中间件整轮确认的契约，不冒充已收齐。

带历史响应 ID 的请求走单聊流。应用只装配一个共享接收器，持续领取反馈，按本轮关联及原任务、用户、平台验证后归位，不按收到顺序分配给模型。回复先保存到 MySQL，再用该条反馈的凭证逐条确认；确认失败保留凭证重试。未完成处理的反馈显式续租，续租同样处理新补齐的反馈，避免窗口占满。未知或不匹配的反馈不分给其他用户、不直接确认删除，保留等待核对。

每次新领取生成新幂等键；同一次结果不确定的重试冻结原键及续租参数。平台 token 从现有会话服务读取，401 仅失效当前 token。子平台请求凭证与顶层反馈凭证不能互换；本模块不调用子平台领取/回复接口，也不调用已删除的 `requests/ack`。

可信工具调用 ID 由 Core 私下传给执行器，与用户、树及节点共同生成稳定本轮 ID；模型不填写。同一调用重试读取原账本，不把相同正文的另一调用错误合并。等待事件在发布前登记，数据库结果回查补足通知竞态；单个等待者取消不取消其他请求。

## 权威状态与恢复

`platform_a2a_calls` 是私有收发账本，保存请求、固定目标、发布回执、已收到反馈、冻结结果、截止时间和关闭待办，不存 token、交付凭证或私有推理。它不替代节点工作区或对话历史。仅当 Core 接受工具动作并提交后，回调标记 `accepted`，其成功响应才能作为后续上下文引用；未接受的半成品不能授权续聊。

账本 `pending → waiting → completed`；取消时进入 `abandoned`。后台重启扫描未完成请求及待关闭广播，发布始终复用原 ID。反馈落库但 ack 未完成时，重领可幂等保存；已冻结结果不因迟到反馈而改变，迟到反馈仅补私有账本后确认。关闭广播失败继续重试。明确发布错误不盲目重试，临时故障在本轮期限内重试；过期仍无法确认发布时明确结果不确定。

工具取消不会强制停止远端模型。业务树删除后账本仍保留，以便关闭广播和处理迟到反馈，不通过外键阻塞树删除；本次不增加审计归档/清理策略。停机先结束问答和助理生产者，再取消共享调度，最后关闭 HTTP 和 SQL 资源。单聊领取幂等键及反馈凭证只驻留内存，进程崩溃后的未确认反馈依赖中间件租约过期重新领取，不宣称即时恢复。

## 配置与启用

配置见 [.env.example](../../../../.env.example)，进程环境优先于项目 `.env`。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `PLATFORM_A2A_ENABLED` | false | 显式装配工具及共享接收器。 |
| `PLATFORM_A2A_RESPONSE_BUFFER_SECONDS` | 5 | 发布确认后首次读取广播前的缓冲秒数。 |
| `PLATFORM_A2A_WAIT_SECONDS` | 90 | 请求建账后整轮等待期限，必须长于响应缓冲。 |
| `PLATFORM_A2A_POLL_SECONDS` | 1 | 后台轮询间隔。 |
| `PLATFORM_A2A_HTTP_TIMEOUT_SECONDS` | 10 | 单次 HTTP 请求总预算。 |
| `PLATFORM_A2A_MAX_CONCURRENT_REQUESTS` | 16 | 私有收发处理及 HTTP 调度并发上限，不替代中间件平台窗口。 |

1. 在本项目 MySQL 库手工执行 018，应用不自动建表。
2. 确认本平台中间件登录可用，目录中目标平台角色与职责正确，子平台已实现 A2A 执行端。
3. 启用开关并重启后端；共享服务校验表结构，缺表或缺中间件配置时启动明确失败。

离线验证不自动修改真实 `.env`、执行业务库迁移或向真实子平台发布请求；实际启用须显式完成上述步骤。工具的启用独立于 `ASSISTANT_ENABLED`，因此可只启用探索工具；个人助理开启时复用同一实例。

2026-10-26 本地环境已按用户要求执行 018 建表，设置 `PLATFORM_A2A_ENABLED=true` 并从命令行重启；合同平台同时设置 `A2A_ENABLED=true`。本地单轮等待已调整为 `PLATFORM_A2A_WAIT_SECONDS=600`（10 分钟），作用于配置生效后新建的 A2A 调用；已有账本截止时间不重写。这是本地运行配置，其他环境仍须单独启用。本次未发起业务广播；启动与迁移证据见[启用记录](../../../../experiment/service-runtime/20261026-234853-enable-a2a/analysis.md)。
