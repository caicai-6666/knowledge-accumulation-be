# Core 图像文件阅读

轻量查看回执由工具独立末尾钩子使用多行模板生成，保留文件 ID、当前页和总页数；正文展示、隐藏及不可读三态分别反馈。持久化只保存隐藏回执，原生图像仍经资料消息注入。展示期引用失效转为 ToolPageUnavailable，不把旧图像当成当前可读内容；失败保留读取位置，不改变原授权和提交回调。 渲染及兼容边界见[工具反馈契约](tool-content-contract.md#core-工具反馈迁移清单)。

## 用途与入口

独立的 `view_image_file` 只阅读用户多图附件中的图像页面。参考 contract-service-be 的文件模型、LRU 驻留、独立阅读位置和临时页面展示；不迁入合同库工具、文件门禁、HTTP 上传或其他业务流程。音频和视频有明确的 `unsupported_type` 反馈，本轮不实现其读取能力。

工具定义位于 [tool/image_viewer.py](../../../../app/agent/core/tool/image_viewer.py)，图像执行器位于 [file/image_viewer.py](../../../../app/agent/core/file/image_viewer.py)。UUID 与磁盘文件沿用[任务附件登记](../../data/question-file.md)。装配 `QuestionAgentService(..., file_service=files)` 或模式工厂的 `file_service` 后，自动给本轮 Core 加入这一个图像工具；共享 Core 的基本工具集合不被修改。


个人助理额外采用[附件授权包装](../../../../app/agent/assistant/tool/image_authorization.py)：先通过原有用户与任务树归属校验，再通过 `FileVisibilityService.get` 确认上传登记属于当前用户、类型一致且 `visibility=public`。私密文件一律拒绝，包括所属用户本人上传的附件；未登记、依赖不可用及登记不一致也不放行。反馈保留具体原因与修正方向，不诱导模型为了读取而自行公开文件。

该包装通过 `QuestionAgentService.file_authorize_wrapper` 注入，仅作用于个人助理的 `view_image_file` 查看器。个人助理工厂接收 `file_visibility`，生产组合根注入已有服务；没有装配该依赖时，附件查看拒绝而不跳过校验。探索模式、注册中心文件工具、HTTP 附件下载及通用文件服务的授权规则不变，不开放他人的公开附件跨用户读取。Core 工具参数、读取实现及渲染钩子不变。

查看器每次读取前、缓存命中、渲染完成及页面再次展示时都重新调用包装后的授权函数。因此公开改为私密后，后续读取和缓存页面再次展示均拒绝；无法撤回此前已经送入模型的图像。无需数据库迁移或新增配置。

## 工具契约

```json
{"file_id":"11111111-1111-4111-8111-111111111111","page_number":1}
```

| 参数 | 含义 |
| --- | --- |
| `file_id` | 当前或历史图像附件的完整 UUID，从“文件ID”原样复制；不是序号、文件名或路径。 |
| `page_number` | 从 1 开始的文件页面顺序。省略或 `null` 表示本轮任务上次成功查看该文件的下一页；首次为第 1 页。 |

只有工具与节点状态成功提交，阅读位置才推进。参数非法、读取/渲染失败或提交失败都不推进；显式越界和顺序读到末尾分别给出稳定错误。重新开始任务或切换探索分支创建独立阅读位置，不继承其他运行的游标。

实际 JSON Schema 的两个参数均有字段说明，拒绝多余字段。工具不接收用户、树、节点、目录、令牌或缓存参数，这些由可信宿主绑定。

## 模型实际看到的内容

调用成功后保留短小的原生 assistant/tool 对；图片不是 tool 中的 JSON 字符串。在其后追加一条资料提醒和一条包含真实 `image_url` PNG 的 user 消息。图像块之前的定位文字由公共渲染器生成：

```text
文件类型: 多图
文件ID: 11111111-1111-4111-8111-111111111111
页码: 1
总页数: 3
```

```yaml
位置: page:1
内容类型: 图像
```

定位文字沿用中文标题、安全正文围栏和 YAML；不显示服务器路径、PDF 后缀、内容哈希、用户/树/节点身份、内部展示编号、缓存或调度说明。图像是资料，不改变工具规则或访问权限。

临时图像默认供 5 次完整主模型响应使用；协议错误和失败工具响应同样消耗机会，构造/计数不消费，网络失败、截断与内部整理不消费。到期后请求中移除图片，轨迹只保留查看记录；再次核对必须重新调用工具。原生推理和私有响应仍完整保存，不受该展示窗口限制。

若上下文整理发生时页面仍需展示，保留其完整工具对及页面引用，不静默丢弃尚未读到的图像。最终预算使用将实际发送的多模态 messages 经既有 vLLM 原生接口计数；整理后仍超硬上限则停止，不以隐藏图片绕过验收。

## 文件驻留与资源释放

[FileModelCache](../../../../app/agent/core/file/cache.py) 默认驻留 4 份文件模型，按最近实际访问更新 LRU，淘汰最久未访问的空闲模型并关闭。租约保护读取中的文件；容量满且候选全部在用时明确失败，不强制关闭。并发同键首次加载合并，模型只能归属一个池；关闭等待在途读取归还后释放。

用户附件以 `(用户、树、文件 UUID)` 定位内存文件模型，不计算内容哈希。每次查看及驻留页面重新展示先核验附件登记归属；命中后直接取得模型和页面，不读取磁盘 PDF，未命中或被淘汰后才经文件服务读取并加载。渲染结束再次检查登记，缓存不能绕过权限。跨任务可复用同一用户和树的文件模型，但阅读游标仍独立。

上传存储以独占创建方式分配 UUID，同一 UUID 的附件不可原地替换；新文件必须使用新 UUID。运行中绕过上传机制修改磁盘内容不属于支持的更新方式，也不会靠重复哈希检查发现。LRU 驱逐只释放派生资源，不删除磁盘文件或附件登记；重开时当前任务游标保留。注册中心远程文件的授权与版本策略见[注册中心文件阅读](registry-file-reading.md)，本地 UUID 复用规则不改变远程请求契约。

[FileModel](../../../../app/agent/core/file/pdf.py) 持有打开文档，按需缓存不可变 PNG 页面，不长期保存 Base64。所有 MuPDF 打开、渲染与关闭共用进程锁，在线程执行，避免阻塞事件循环及多线程不安全。拒绝非真实 PDF、密码文件、空/损坏文件；页面按默认最大 2 倍比例、32 像素 patch、2048 视觉 patch 预算缩放。此预算仅控制图像分辨率，不替代实际模型 token 计数。

服务自建池在 `close()` 关闭；显式传入 `file_cache` 时，其容量和关闭职责仍由外部宿主控制，本服务不会依据配置重新调整该池。取消等待不会强制中断在途 MuPDF；租约归还后再完成池释放。

## 运行配置

[配置加载器](../../../../app/config/agent.py)读取项目根目录 `.env` 和进程环境，配置示例见 [.env.example](../../../../.env.example)：

```dotenv
AGENT_FILE_CACHE_MAX_FILES=4
AGENT_PAGE_DISPLAY_ROUNDS=5
```

| 配置 | 默认值 | 对应 CoreSettings 字段与含义 |
| --- | --- | --- |
| `AGENT_FILE_CACHE_MAX_FILES` | 4 | `file_cache_max_files`：每个服务自建 LRU 池可驻留的文件模型数量，不是图片页数或字节数。 |
| `AGENT_PAGE_DISPLAY_ROUNDS` | 5 | `page_display_rounds`：每次打开的可折叠正文可见的完整主模型响应次数；不是同时展示的图片数。当前图像阅读使用此公共窗口，后续可折叠文本/表格同样遵循。 |

两项只接受大于 0 的十进制整数。缺少键使用默认值；显式空值、0、负数、小数或布尔文本使装配失败，不静默回退，错误不回显输入值。不对配置做变量插值。

助理和探索模式的 `build_core` / `build_service` 未传 `options` 时自动加载。优先级为进程环境 > `.env` > 默认值；如果显式传入 `CoreSettings`，整体使用该对象并跳过环境加载，不与 `.env` 混合。配置在构造时形成快照，修改后需重建服务或重启进程；运行中及 `with_registry` 克隆时不重新读取。

底层 `AgentCore` 保持显式依赖，不自行读取 `.env`。直接使用它时传入加载结果：

```python
from app.agent.core import AgentCore
from app.config.agent import load_agent_core_settings

core = AgentCore(model_settings, options=load_agent_core_settings())
```

只导入模块不读取配置，不创建连接或文件池。测试通过显式配置文件放在 `tests/tmp` 或传入 `CoreSettings` 隔离真实配置。

## 提交与错误恢复

图像工具声明 `return_types=('foldable',)`，绑定自己的 `resolve_page`。读取器返回统一 `ToolExecutionResult`，其 `content.pages` 是轻量页面引用；内部 `ToolExecution` 仅另带提交回调。页面引用在解析时校验签发记录、文件 UUID 和登记归属，重开同页生成新的展示标识；通用声明、状态和折叠规则见[公共工具契约](tool-content-contract.md)。数据库确认后才推进位置并登记展示。PNG、Base64 和临时提示不写入 `TaskContent.exchanges`、工作区或历史模型消息；历史只保留轻量工具对。窗口与查看器按运行结束释放，文件模型按服务生命周期管理。

可反馈的查看失败只在连续纠错中携带临时原生调用与最小反馈，共用原有连续错误上限。动作完整成功后清除整段失败轨迹；原始生成保存在私有记录。提交失败直接停止、不重放工具；已经提交的页面在重新解析时若失效，也停止生成，不用占位图片冒充成功。底层路径、异常堆栈及内容字节不进入错误反馈。
