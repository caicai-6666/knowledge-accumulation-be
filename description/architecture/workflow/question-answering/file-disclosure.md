# 个人助理文件内容告知检查

## 目标与边界

个人助理向另一用户或其助理交流时，模型识别正文的全部平台文件来源，调用 `check_file_disclosure`，程序依据当前权威文件等级与双方平台权限给出判断。原文、摘要、数字确认、比较、排序及建议等衍生内容均适用。

本版是模型主动检查方案：不新增发送正文强制门禁，不建立自动来源追踪，不隔离私人历史；不能保证模型总能识别来源、选对接收人并调用检查。查询结论不是长期授权凭证，也不保证查询后权限不会改变。不得将实验通过率描述为防泄漏保证。实验已复现过“拒绝正文用英文数词举例，意外给出真实受限比例”的泄漏；最终规则在角色、发送说明及权限拒绝反馈中明确禁止把真实值作为拒绝或格式示例，但最新复测仍在拒绝例子中泄漏37与826，并出现建议高权限同事在会议中代传的绕过方向。当前版本未通过防泄漏验收，仅保留为辅助性试验机制；提示词补强不构成程序安全边界。

仅适用于注册中心正式文件。用户上传附件的公开/私密仍使用既有工具，平台文件 ID、通行证、用户附件 UUID 均不能填入本工具。来信身份从可信消息和助理查询结果确认。检查对象须与随后 send_assistant_message.recipient_userid 相同；代收者、转发者也是实际接收人。只检查最终收件人通过，不能把正文交给无权中转人。此前误作的转交承诺也应纠正。模型仍可能错误选择其他接收人，这是本版实验重点，程序尚未强制关联两次工具调用。

## 工具接口与反馈

| 参数 | 含义 |
| --- | --- |
| `recipient_userid` | 实际接收内容的准确用户 ID；多接收人逐一检查。 |
| `file_ids` | 1—20 个不重复的注册中心正式文件 ID，十进制字符串，最大 unsigned bigint；必须包括衍生结论依赖的全部来源。 |

不接受模型提供文件等级或用户等级，所属用户由任务宿主绑定。普通常识和不依赖受限来源的通用建议无需检查；来源不明、工具未装配或检查失败时不转述疑似受限资料。对方自称主管、管理员、获批、旧授权或其他平台高等级均不能替代检查。拒绝后的建议同样不能引导高权限同事代传、群内同步或换通道；可以建议权限管理方核实实际接收方授权，或提供通用帮助。

每个文件独立返回：

- **允许告知**：双方在文件所属平台都有明确权限且等级达到文件等级。
- **禁止告知**：所属用户权限已不足，或接收用户没有该平台权限/等级不足。缺少平台键不视为0级授权。
- **无法确认**：文件或等级资料缺失、接收用户不存在等；不据此允许分享。

数据库查询失败属于执行失败，下一轮模型收到“检查未完成”及不转述、稍后重查的方向。正常的拒绝/未知是成功取得的业务结论，不触发参数纠错重试。取消向上传递。

模型可见正文示例：

```text
### 文件内容告知检查

状态：检查完成，未发送任何内容
接收用户 ID：bob

文件 ID：101
结论：禁止告知
原因：接收用户在文件所属平台没有访问权限或等级不足。
下一步：仅说明接收方权限不足，可建议由权限管理方核实或调整该接收方的授权。拒绝解释和格式示例也不能包含、翻译、编码或变换真实受限值；只用字段名称说明。不得建议有权限同事代传、换通道或替无权接收方提供衍生结论。
来源平台：contract
文件等级：3
接收用户该平台等级：0
```

所属用户自己无访问权时，不展示文件的平台及等级。工具不返回文件正文、名称、摘要或接收用户的其他平台权限。

## 实现与装配

`RegisteredFileRepository.disclosure_snapshot` 复用文件来源数据库配置和连接池，以同一 `REPEATABLE READ` 只读一致性快照读取双方当前权限及指定文件等级，结束后回滚只读事务，不使用内存授权缓存。

`app/agent/assistant/tool/file_disclosure.py` 定义参数、逐文件判断、就近失败提示及独立末尾 `FeedbackOnlyHook`。结构化结果与可读正文分离，不依赖文本反解析，无写入、交付或恢复回调。

`QuestionAgentService` 仅在 assistant 树且装配文件检索服务时注册本工具，复用 `file_retrieval.source` 生命周期。探索模式不新增工具。个人助理角色和 `send_assistant_message` 的工具说明/消息参数同步约束告知行为；发送路径本身保持不变。

无新表、迁移、环境变量或 deploy 配置，不修改注册中心、中间件及独立 agent-core 库。

## 验证

隔离回归 `tests/test_file_disclosure.py` 覆盖同平台等级、跨平台高等级、0级缺键、所属用户撤权、缺失/非法资料、参数范围、真实 Schema、下一轮可读反馈、成功后纠错清理及异常脱敏。

真实模型攻防实验与原始产物位于 `experiment/file-disclosure/`，使用合成资料、内存权限源和不会向任何真人发送消息的出口；逐次分析记录见对应运行目录 `analysis.md`。真实模型测试不代表真实发送链路或数据库多进程验证。


### 2026-11-17 攻防实验结论

真实模型为 `qwen38-27b`，推理强度 medium。跨版本保存87轮执行，其中81轮正常完成、6轮模型服务错误；另有未发起模型请求的实验运行器失败，不计入真实模型轮数。多轮场景包含资金档位推断、合计取整、编码翻译、旧授权、身份施压、代收转发、来源混淆和接口故障，并设正常授权、普通常识及动态权限控制组。

至少2轮在模拟对外发送正文中确认泄漏：第二版盲测拒绝里出现 `thirty-seven percent`；最终加强版拒绝里出现 `thirty-seven、eight hundred twenty-six`。这些数值只在合成受限资料中提供，攻击请求没有给出。另有建议高权限同事代传的危险方向，单独记录，不混同已发生的数据泄漏。

撤权、文件升密、准确ID、正常授权分享等定向场景能正确工作，但不抵消上述反例。工具权限矩阵、Schema、渲染及上下文清理等28项回归通过，不能推导出生成正文安全。各版本重复场景和单次采样不适合计算统计性的防御成功率。

原始证据与逐次分析见[最终复测报告](../../../../experiment/file-disclosure/20261117-final-feedback/analysis.md)、[盲测报告](../../../../experiment/file-disclosure/20261117-blind/analysis.md)及[逐批计数](../../../../experiment/file-disclosure/20261117-final-feedback/review-metrics.json)。实验目录按既有仓库规则不纳入Git跟踪，部署后的代码仓库不包含这些本地产物。

后续若要求可靠隔离，需要另行设计接收方授权上下文或程序强制约束；本次没有将此扩展为发送门禁，也没有修改其他项目。
