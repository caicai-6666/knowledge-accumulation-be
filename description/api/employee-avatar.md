# 员工头像补齐

## 用途与授权

注册中心人工刷新组织架构时，可在员工资料保存后逐人调用知识后端补齐头像。头像文件统一由知识后端存储及读取，已有头像不覆盖，不新建员工，不修改权限和任职资料。

`POST /knowledge-accumulation/api/internal/employee/avatar`

本地开发入口增加 `/dev` 前缀。请求 `Authorization: Bearer <本次管理员用户token>`，不是平台 token。注册中心只转发本次刷新调用者的用户凭据，不保存令牌或用于脱离用户请求的后台重试。

知识后端先用现有中央用户认证确认身份，再读取 SQL `platform_admins` 对应的 `managed_platforms`，仅允许有 `registry` 管理关系的用户。普通登录、其他平台管理员、文件高等级和开发模拟配置均不能替代该关系。当前接口验证管理员用户身份，不证明请求网络来源一定是 registry；持有有效管理员用户凭据的调用方均受同一检查。

不新增中间件接口或修改中间件授权。中央服务或数据库不可用时拒绝写入。

---

## 请求与成功响应

请求类型为 `application/json`，不允许查询参数和额外字段，体积不超过16KiB。

```json
{"userid":"employee-123","avatar_url":"https://static.dingtalk.com/example.png"}
```

| 字段 | 约束 |
| --- | --- |
| `userid` | 必填，1—128字符，无首尾空白；现有员工的准确ID。 |
| `avatar_url` | 必填，可为null或空串；非空时最多4096字符，是钉钉员工资料中的头像地址。 |

复用 `AvatarStore` 的HTTPS域名白名单、禁止凭据和非443端口、逐跳重定向校验、下载大小/像素限制及无损WebP转码。默认允许 `dingtalk.com`、`alicdn.com`、`aliyuncs.com` 及其子域，实际以 `AVATAR_ALLOWED_HOSTS` 为准；不提供任意URL代理。使用现有钉钉请求转发配置。

```json
{"userid":"employee-123","status":"created","avatar_url":"0123456789abcdef0123456789abcdef.webp"}
```

| 状态 | 含义 |
| --- | --- |
| `created` | 本次条件更新已提交，返回保存的头像文件名。 |
| `existing` | 员工已有头像，或并发调用先完成；返回已有文件名，本次不覆盖。 |
| `skipped` | 员工存在且头像为空，但未提供头像地址；文件名为null，无写入。 |

先确认员工存在，再检查是否已有头像，最后下载。已有头像的调用不会下载或校验传入地址的域名/图片内容，但仍要求请求Schema合法。返回文件名可用于既有 `/resource/avatar/{filename}`，不返回磁盘目录。所有响应禁用缓存。

## 错误与调用方处理

错误正文统一为 `{"detail":"说明"}`，不回显令牌、带签名URL、SQL或任意异常原文。

| HTTP状态 | 原因及处理 |
| --- | --- |
| 401 | 用户Bearer缺失或中央登录无效；重新登录，不以平台token替代。 |
| 403 | 没有registry管理关系；不降级为普通用户写入。 |
| 404 | 目标员工不存在；先完成员工资料同步。 |
| 413 | 请求体超过16KiB。 |
| 422 | 参数、类型、地址、图片格式或资源限制不符合要求。 |
| 499 | 读取请求体时客户端断开，通常无法收到响应。 |
| 503 | 中央认证、数据库、下载或文件操作失败，或提交结果尚未确认；后续可幂等重试。 |

注册中心应隔离单人失败，不回滚已完成的组织资料刷新；只累计成功和失败数量，下次人工刷新重试。无头像可直接跳过接口。`existing`是正常结果，不是补齐失败。

## 并发、清理与部署

`MySQLEmployeeRepository.fill_avatar` 在事务内执行 `UPDATE ... WHERE avatar_url IS NULL OR avatar_url=''`，由数据库仲裁并发，再锁定读取并返回最终引用。头像先原子存盘，再更新数据库；竞争败者删除自己的候选文件。重试保持现有引用，不更换文件名。

数据库失败或请求取消后回读引用：确认候选文件未被采用才清理。若commit结果不明且回读也失败，保留文件并记录待核对日志，避免误删已提交的头像。进程崩溃发生在文件落盘和SQL提交之间仍可能留下孤立文件；本接口不新增定时清理或跨文件系统/数据库分布式事务。

主要实现为 `app/router/employee_avatar.py`、`app/schema/employee_avatar.py`、`app/service/employee_avatar.py` 及员工仓库，`app/main.py` 复用已有仓库、头像存储和认证服务装配。

无新增依赖、环境变量、表或部署服务；更新代码后重建知识后端镜像。未改动其他项目代码。

## 验证边界

`tests/test_employee_avatar_fill.py` 覆盖HTTP鉴权/参数、已有头像不下载、缺失员工、空头像跳过、恶意域名与重定向拒绝、真实无损转码、并发候选清理、数据库失败、提交结果不明、取消清理及SQL条件更新/事务回滚。与既有头像缓存、无损编码测试一起执行；测试目录显式覆盖为 `tests/tmp/`，结束删除。

使用模拟中央身份、仓库及SQL连接，不访问真实用户或业务库；真实MySQL跨进程竞争和registry到知识后端的运行中HTTP链路尚未联调。
