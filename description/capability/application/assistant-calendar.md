# 个人助理日程集查询与查看

## 用途与当前范围

个人助理通过 `search_calendar_events` 按员工和时间范围查询钉钉主日历，获得任务内隔离的日程结果集，再通过 `view_calendar_query` 分页读取正文。底层使用 `eventsview`，按钉钉规则展开循环日程。

> **查询与查看分离：** 查询工具只返回 ID、数量和分页信息；查看工具通过可折叠页面提供日程正文，翻页只读已保存的快照，不再请求钉钉。忙闲查询、日程写入、请假及外出查询均未接入。

与[个人助理消费](assistant-consumption.md)共用生命周期；[公共结果池](../../../app/agent/core/query_pool.py)提供结果发布、隔离和释放，不修改问答树或数据库结构。


两个日程工具各自注册末尾渲染钩子：查询正文展示用户 ID、带时区的起止时间、保留数量及完整性，空结果不生成查询 ID；查看提供可见、隐藏、不可读三态回执。页码越界与查询失效保留查询池的定向反馈，失败不推断员工空闲。

## 查询工具接口

```json
{
  "userid": "从员工目录取得的准确userid",
  "start_time": "2026-11-02T00:00:00+08:00",
  "end_time": "2026-11-03T00:00:00+08:00"
}
```

| 参数 | 要求 |
| --- | --- |
| `userid` | 本项目已登记员工的准确 userid，最长 128 字符且不含空白；可指定本人或其他员工，不接受姓名替代。 |
| `start_time` | 带时区的 ISO 8601 开始时间，不接受无时区时间或数字时间戳。 |
| `end_time` | 带时区的 ISO 8601 结束时间，必须晚于开始，按 UTC 经过时间计算最多 31 天。全天查询使用次日零点。 |

实际 Pydantic JSON Schema 的每个字段都有说明；JSON 解析保留严格日期模式，范围错误就近生成定向修正提示。窗口参数直接传给钉钉 `timeMin/timeMax`，日程匹配及循环展开遵循上游语义，不自行改写日程时间。

有结果时返回以下元数据：

| 字段 | 含义 |
| --- | --- |
| `query_id` | 本次日程集引用，不是钉钉日程 ID，不能传给记忆或员工目录查看工具。 |
| `userid`、`start_time`、`end_time` | 实际查询对象和窗口。 |
| `total` | 已保留的日程条数，截断时不代表全部数量。 |
| `total_pages` | 以每页 10 条计算的页数，使用 `view_calendar_query` 查看。 |
| `truncated` | 是否因为条数或请求页数上限未完整取回结果；为 true 时建议缩小时间窗口。 |
| `content_available` | 有结果集时为 true，可调用查看工具；空结果为 false。查询回执本身不含正文。 |
| `message` | 查询状态和当前可执行的后续动作，不含日程正文。 |

完整空结果返回 `total=0`、`total_pages=0`、`truncated=false`，不生成 `query_id`。达到页数上限但没有有效记录时仍明确 `truncated=true`，不能据此判断没有日程。主日历没有记录不代表员工一定空闲、在岗或没有其他渠道的安排。

## 查看工具接口与渲染

```json
{"query_id":"search_calendar_events 返回的完整查询ID","page":1}
```

两个参数均必填。`query_id` 只接受本任务日程池中的结果引用，不接受日程 ID 或其他查询池标识；`page` 为从 1 开始的整数，支持跳页和重复查看。成功回执只含 query_id、page、total_pages、total、has_next；正文作为可折叠页面提供，重复打开生成新的展示引用。只有提交成功才推进页码和最近使用顺序；越界、失败和自动解析均不推进。页面引用签名绑定查询集、页码及本查看器，篡改、跨查看器、淘汰或任务关闭后不能读取。

页面先展示员工姓名和 userid、查询窗口、显示时区、查询完成时间、页码与条数，再按日程独立成块展示：

- 完整日程 ID、标题、时间、地点、组织者、日程状态、查询员工邀约响应。
- 已返回参与人员的姓名、响应状态、查询员工标记及可选参与标记。
- 有返回时显示会议室预约状态；描述保留原文段落，空描述显示“未填写”，缺失地点等显示“未提供”。

| responseStatus | 展示 |
| --- | --- |
| accepted | 已接受 |
| needsAction | 待响应 |
| declined | 已拒绝 |
| tentative | 暂定 |
| 缺失、未知或不合法值 | 响应状态未知 |

按查询时取得的 unionId 匹配查询员工，不通过名字猜测；列表中未返回唯一匹配人员时说明响应状态未知。日程 confirmed/取消状态与个人邀约响应分别展示，邀约响应不能代表实际出席，也不转换为官方 BUSY/TENTATIVE 忙闲结论。

有时刻的时间统一转换为 Asia/Shanghai（UTC+08:00），跨天完整展示两端日期；全天日期型日程显示“全天”、开始日期及结束日期边界，不对原始日期做时区平移，不擅自把结束边界写成包含当天。日期/时间按上游快照保留，不根据名称推算时间。

`eventsview` 的参与人员完整性未单独核验，因此显示“已返回 N 人，完整性未确认”，不称为总人数；没有记录也不能推断无人参加。本轮不增加参与人接口请求，避免翻页时把新状态混入旧快照。

描述最多展示前 6,000 字符，人员最多前 100 条，会议室最多前 100 条，超出时明确标注；普通单行字段也限制长度并标注截断，日程 ID 完整显示。日程集本身截断时页首显示“已保留 N 条（非完整结果）”。外部单行字段的控制符转义，描述每行加资料块前缀以保留段落并区分正文与页面结构。仅展示白名单业务字段，不展示企业 ID、unionId、请求追踪字段或创建/更新时间。

示例：

```text
【1】技术讨论会
日程 ID：<完整日程ID>
时间：2026-11-02 15:00:00 至 2026-11-02 16:00:00
地点：202会议室
组织者：Louis 张琦
日程状态：已确认
查询员工的邀约响应：已接受

参与人员（已返回 8 人，完整性未确认）：
- James 蔡昌言：已接受〔查询员工〕
```

上述人员列表仅为文档节选。真实页面会展示本页各日程的已返回人员，达到展示上限时明确说明。

## 身份、分页与快照

1. 服务端查询权威员工仓库；员工必须存在且返回 userid 与请求一致。离职状态不作为本工具的额外拒绝条件；钉钉侧身份已失效或不可见时按实际失败返回。
2. 通过钉钉通讯录详情取得该员工 unionId，模型不能直接注入 unionId、应用凭据或任意日历 ID。
3. 使用企业内部应用凭据查询 `primary/eventsview`，每次请求最多 100 条，处理 `nextToken`。
4. 按事件 ID 和发生时间区分循环实例，完全相同的重复记录去重；同一键内容冲突、游标重复或任意一页失败，整次失败，不发布已取得的部分记录。
5. 默认最多保留 1,000 条、读取 20 页；达到上限返回明确截断结果，保留钉钉返回顺序。该快照是完成查询后固定的本地视图，不保证分页期间上游日历具有事务一致性。
6. 查询成功后先准备结果，Core 检查点提交完成才由 `after_commit` 发布 ID。未提交、失败、取消或任务结束后迟到的回调不会恢复结果池。

每个助理任务独立创建池，容量 10 个结果集、每页 10 条。与其他员工任务、记忆、助理目录、画像查询完全隔离。结果保存在任务内存中，任务结束清空，不建表、不写 `data/`、不把完整日历写入工作区。每个结果项引用同一份不可变的查询元数据：时间窗口、查询完成时间、目标 unionId、是否截断；员工 userid 和姓名随结果保存。翻页页首从快照读取，不依赖模型回忆或实时员工资料。

当前访问范围为本项目人员目录中的员工，钉钉进一步校验应用授权和日历访问权限；本工具未增加仅本人或按部门的额外访问策略。企业若需更窄范围，须在服务端追加明确规则，不能只依赖提示词。

## 装配、依赖与错误边界

| 模块 | 职责 |
| --- | --- |
| [search_calendar_events.py](../../../app/agent/assistant/tool/search_calendar_events.py) | 查询参数 Schema、定向反馈、结果池与工具注册；仅返回查询元数据。 |
| [view_calendar_query.py](../../../app/agent/assistant/tool/view_calendar_query.py) | 查看参数 Schema、页码反馈、签名页面和可折叠解析。 |
| [calendar_rendering.py](../../../app/agent/assistant/calendar_rendering.py) | 日程块、时区、邀约响应、完整性及截断展示。 |
| [calendar.py 模型](../../../app/model/calendar.py) | 日程时间、事件和分页响应模型；保留额外业务字段，忽略请求追踪字段。 |
| [dingtalk_calendar.py](../../../app/infrastructure/dingtalk_calendar.py) | 复用钉钉认证，读取 unionId 和日程视图；没有日程写入方法。 |
| [calendar.py 服务](../../../app/service/calendar.py) | 人员边界、分页去重、快照和查询总超时。 |
| [main.py](../../../app/main.py) | 助理启用时装配共享读取服务和 HTTP 客户端，退出时关闭。 |
| [assistant_consumer.py](../../../app/service/assistant_consumer.py) | 每任务注册工具，创建并释放独立结果池；探索模式不注入。 |

复用 `DINGTALK_CORP_ID`、`DINGTALK_APP_KEY`、`DINGTALK_APP_SECRET` 和 `DINGTALK_TIMEOUT_SECONDS`，与现有员工资料读取使用同一组应用凭据来源。要求通讯录读取权限/可见范围，以及 `Calendar.Event.Read`；不需要 `Calendar.EventSchedule.Read`。无新增环境变量、SQL 迁移或外部 HTTP 业务接口。启动助理需继续满足现有助理开关和依赖条件。

每个 HTTP 请求沿用钉钉超时设置；完整人员查询、身份映射和分页默认最多 60 秒。HTTP 401 只刷新应用凭据重试一次；权限拒绝、限流、参数/日历不可用、上游失败分别给出安全反馈，不回显上游异常原文或访问凭据。响应单页超过 4 MiB 拒绝；响应缺少有效事件时间或列表不能部分发布。

实测钉钉空结果可能只返回 `requestId` 并省略 `events`；仅在 HTTP 成功、无业务错误、响应键只有 `requestId/nextToken` 且请求标识非空的明确形态下转为空列表。空对象、带业务错误码或异常字段的缺失列表仍失败。请求标识仅用于适配成功形态，不进入模型结果。

所有业务修复提示维护在产生条件的分支旁。工具失败只进入连续纠错上下文，成功后沿用 Core 清理整段失败轨迹，私有生成审计仍保留；日程正文仅在成功查看后通过可折叠资料进入模型上下文，不复制到工具回执；未通过检查的页面不发布，页面解析不推进页码或刷新结果池热度。
